## Gemini exam: more questions in every field of the project (`training/gemini_exam.py`, notebook cell F4)
- **Two examiners, Gemini and Groq (`gpt-oss-120b`), whichever keys exist** (`GEMINI_API_KEY`, `GROQ_API_KEY`; the cell never stops to ask for a key): they share the questions of every field, and `combined_judge` has **both** grade every answer (the mean is the score, each judge's mark is kept, and the table shows each judge's total and the share of answers on which they differ). One judge's bias no longer decides the result. `GroqClient` has the same interface as `GeminiClient` (Bearer header, retries, cache, key never stored). The exam file is `data/exam.jsonl`.
- Gemini is the **examiner**: it writes extra test questions for 10 fields (vendor identification, syslog, read-only commands, configuration changes, troubleshooting, incident explanation from measured facts, safety and refusal, CCNA, Arabic, dependency reasoning; English and Arabic), the tuned model answers them, Gemini grades each answer 0-2 against a rubric it wrote, and **our own knowledge base checks every command** in the answers (invented or unsafe) without any LLM, so the judge is not trusted alone. The questions are saved (`data/gemini_exam.jsonl`) so every run asks the same ones; results go to `reports/gemini_exam_<run>.json`.
- Gemini output is used to measure, **never as training data** (the Gemini API terms do not allow building competing models from its output).
- `GeminiClient`: key in a header (never in a URL, never printed, never written to the cache), the model is picked from the API's own list (the newest stable text flash model; names change often), retries on 429 and 5xx, answers cached on Drive. The Colab secret must be named `GEMINI_API_KEY` (secret names cannot contain spaces; "Gemini API Key" is only the name field in Google AI Studio).
- `model_eval.load_adapter_model` and `answer_batch` now hold the adapter loading (4-bit base + LoRA, with the torchao guard) shared by F3 and F4. The notebook has 29 cells.
- Verified: 12 new tests with a fake HTTP layer (key handling for both services, model choice, retries and cache, JSON parsing, question validation, the questions shared between two examiners, the saved exam, the two judges and where they differ, the local command check, grading and the report, cell F4); 303 backend tests pass. ## One command that collects every outside source into one folder: `training/collect_data.py`
- Until now the outside data was downloaded inside the notebook at every run and never stored anywhere the user could look at. `collect_data.py` gathers all sources into `RootIQ_AI/data/external/<full|smoke>/` with a `manifest.json` (source, tier, licence, rows, sha256, revision) and a `README.md`, and reuses files already there. Tiers: `train/` (chat rows, licence approved: MikroTik Q&A, witfoo syslog, ntc-templates captured CLI output), `eval/` (the CCNA test), `reference/` (NetConfEval x2, SNMP agent traces, MikroTik docs), `restricted/` (five sets with no usable licence or unstated origin; only with `--accept-licence-risk`, never read by the notebook). `--kaggle owner/name` downloads a Kaggle dataset only if its metadata licence is open.
- Cell B4 now calls it (train tier only in a smoke run; train, eval and reference in a full run) and mixes only `train/` into the training data. A smoke run writes to `smoke/` so its small files never reach a full run. A source that fails is recorded and retried on the next run without stopping the others.
- The licence rule is unchanged and guarded by tests: a source reaches `train/` only if the catalog approves it (`external.allowed`) or its LICENSE file is Apache-2.0 (`ntc_source.licence_ok`); no restricted, evaluation or reference set can be converted into training rows.
- Run against the real sources (Hugging Face through its REST API because `datasets` is not installed on the development machine, ntc-templates from GitHub): 1,532 train rows (649 MikroTik Q&A from the first 600 rows per split, 500 syslog, 383 CLI output), 343 CCNA test rows, 1,213 NetConfEval rows; three reference sources hit the REST API's rate limit and were recorded as failed without stopping the run. ## Fix: cell E1 on Colab (found when exporting the merged model)
- Colab ships `torchao` 0.10.0, and the newest `peft` raises "Found an incompatible version of torchao ... only versions above 0.16.0 are supported" when the adapter is loaded. E1 now removes an old `torchao` first (the notebook does not use it; the 4-bit weights come from bitsandbytes). In a local environment it stops with the exact command to run instead of changing the user's packages.
- The second Colab error after that ("We need an `offload_dir` to dispatch this model ... layers.26 ... need to be offloaded"): `device_map="auto"` saw almost no free GPU memory, because a finished training run still holds most of it, and tried to push layers to disk. E1 now merges on the CPU (`device_map={"": "cpu"}`, bf16, about 8 GB of RAM), which needs no GPU memory and gives the same merged weights.
- E1 used `del trainer, tuned, model` first, so after a failed attempt it could not be rerun (NameError). It now releases them tolerantly (also the traceback of a failed attempt, which keeps a half-loaded model alive), so the cell can be rerun.
- E1 takes the base model, run name, smoke flag and decision from the evaluation report (`reports/eval_report.json`), and loads the tokenizer from the adapter folder, so it also works after a runtime restart (run cells 1 and 3 first).
- `torch_dtype` (deprecated) is replaced by `dtype` on transformers 4.56 or newer.
- E1 ends with `os.sync()` and says that Colab uploads the ~8 GB file to Drive in the background (it appeared in Drive about 15 minutes after the cell ended, `model.safetensors` = 8,044,982,080 bytes for the smoke run), how long to keep the runtime connected, and how to force the upload (`drive.flush_and_unmount()`, then run cell 1 to mount Drive again; E1 cannot be rerun while Drive is unmounted).
