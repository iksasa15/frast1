# RootIQ vendor-knowledge dataset (data card)

Generated by [`../build_dataset.py`](../build_dataset.py) from `backend/app/knowledge/data/` — do not edit the JSONL by hand
(`pytest backend/tests/test_training_data.py` fails if the files are not exactly what the generator produces).

## Files (`generated/`)

| File | Purpose |
|---|---|
| `train.jsonl` | fine-tuning |
| `val.jsonl` | eval loss during training |
| `test_seen.jsonl` | same facts, unseen wording/variant (did it learn the KB and the output formats?) |
| `test_unseen.jsonl` | whole KB items never seen in training (does it invent commands or say it does not know?) |
| `manifest.json` | counts per task / split / language, KB fingerprint, sha256 of every file, generator version and seed |

## Row schema

```json
{
  "id": "a3f1c0d29b7e",
  "task": "command_lookup",
  "lang": "en",
  "vendor": "juniper",
  "group": "cmd/juniper/junos/show_interface_errors",
  "split": "train",
  "messages": [
    {"role": "system", "content": "You are RootIQ's Network Vendor Advisor. ..."},
    {"role": "user", "content": "On Juniper Networks (Junos OS), which command shows: ..."},
    {"role": "assistant", "content": "On Juniper Networks (Junos OS): `show interfaces ...`. These are read-only inspection commands."}
  ],
  "meta": {"gold": {"...": "machine-checkable labels"}, "must_include": ["show interfaces ..."]}
}
```

Train with `messages` only (chat template of the base model); `task`, `group`, `meta` are for splitting and scoring.

## Tasks

`identify`, `syslog`, `command_lookup`, `command_translate`, `problem_diagnose`, `incident_vendor_plan`, `vendor_profile`,
`version_parse`, `config_model`, `safety_refusal` (counts: see `manifest.json`). External rows, when enabled in the notebook, carry `task` =
`ext_mikrotik_qa` / `ext_syslog_artifact`, are `train`-only and never appear in the committed files.

## Provenance and licence

* Everything in `generated/` is produced from the project's own knowledge base and templates; it contains no text copied from
  vendor manuals or third-party datasets. The knowledge base was written from general public knowledge (command syntax, syslog
  formats, OID numbers checked against the IANA registry) and is marked per vendor with `coverage` and `confidence`.
* The data contains no credentials, addresses of real networks, or personal data (tested).
* Third-party datasets are listed with their licences in [`../catalog/CATALOG.md`](../catalog/CATALOG.md); downloads go to `external/` (git-ignored).

## Known limitations

* Labels are exact for the KB, but the KB itself is series-level (families, not every SKU) and was not captured from real devices.
* 31 of 43 vendors are identification-only: for them the data teaches identification and *abstention*, not commands.
* Arabic prompts/answers are templates around KB text; the KB's problem causes and capability descriptions exist in English only, so Arabic answers embed them in English.
* Small tasks (`syslog` test sets, `safety_refusal`) have few test rows; the evaluator flags `low_n`.
